# @w2agent/wordpress

WordPress plugin for [w2agent](https://w2agent.dev) — AI agent discoverability via `llms.txt`, plus an optional A2A `agent-card.json`.

## Install

**Option A — WordPress Plugin Directory** (once approved):

Search "w2agent" in **Plugins → Add New** in your WordPress admin.

**Option B — Manual:**

1. Download `w2agent-plugin.php`
2. Create `/wp-content/plugins/w2agent/` and place the file there
3. Activate in **Plugins → Installed Plugins**

## What it does

- Serves `/llms.txt` dynamically from your published, public posts, pages, and searchable custom post types (password-protected items are left out; the result is cached for up to one hour and cleared on any post change or site title change; filter the types with `w2agent_post_types` and single items with `w2agent_include_post`). `/llms-full.txt` is not served by this plugin
- Works under a subdirectory install (`/blog/llms.txt`, needs pretty permalinks); on multisite, `data/agent-card.json` is served by the main site only
- Yields the front end to the plugin generated by `w2agent integrate` (installed in `wp-content/plugins/w2agent-site/`) when both are active
- Serves `/.well-known/agent-card.json` only if you add `data/agent-card.json` (generate it with `w2agent generate <url> --format agent-card --a2a-endpoint <url>` when your site runs an A2A agent); otherwise the path 404s
- Adds AI discovery `<link>` tag to all pages
- Reads the `robots.txt` WordPress serves. When `User-agent: *` blocks the whole site, it appends one group that allows the AI user and search agents (for example ChatGPT-User, Claude-User, OAI-SearchBot) with `Allow: /`. It skips any agent your robots.txt names, never changes or removes a line, adds no `Sitemap:` line, and does nothing when "Discourage search engines" is on or when a physical `robots.txt` file exists (the web server serves that file)
- Notifies w2agent.dev when a published page, post, or other type listed in `llms.txt` is published, updated, unpublished, trashed, or deleted (optional, needs a Site Slug and API Key; drafts, menu items, and non-listed types send nothing)

## Settings

Go to **Settings → w2agent** to:

- View active endpoints
- Enter your Site Slug and API Key from [w2agent.dev](https://w2agent.dev) to enable automatic re-crawling

## End-to-end test

`pnpm test:e2e` (from this package) runs both plugins on real WordPress in Docker: standalone plugin first, then `w2agent integrate --platform wordpress --install`, then checks for `llms.txt` content and caching, WebMCP loading, webhooks, subdirectory and multisite installs, activation order, and `php -l` under PHP 7.4 and 8.3.

Prerequisites: Docker, and `pnpm build` at the repo root (the script uses `packages/cli/dist`). It creates containers and a network named `w2agent-e2e-*` on free local ports and removes them on exit. It exits non-zero on any `FAIL` or `PRECONDITION-FAILED` line. It is not part of `pnpm test`.
