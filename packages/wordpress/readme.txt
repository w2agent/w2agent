Make your WordPress site discoverable by AI agents. Dynamically generates llms.txt from your content, and serves an A2A agent-card.json if you provide one.

== Description ==

w2agent makes your WordPress site AI-ready by automatically generating the files that AI agents and language models use to understand and interact with your site.

**What it does:**

* Serves `/llms.txt` — dynamically generated from your published, public posts, pages, and searchable custom post types (password-protected items are left out)
* Serves `/.well-known/agent-card.json` only if you add `data/agent-card.json` — publish one only if your site runs an A2A agent (`w2agent generate <url> --format agent-card --a2a-endpoint <url>`)
* Adds an AI discovery `<link>` tag to all pages
* Merges AI-friendly rules into your robots.txt
* Automatically notifies the w2agent platform when you publish or update content

**Dynamic content generation:**

The plugin generates llms.txt dynamically from your WordPress database — no static files to maintain. The result is cached for up to one hour and cleared when you publish, edit, trash, or delete a post, or change the site title or tagline.

== Installation ==

1. Upload the `w2agent` folder to `/wp-content/plugins/`
2. Activate the plugin through **Plugins → Installed Plugins**
3. Visit **Settings → w2agent** to verify your endpoints are working
4. Optionally, connect your w2agent.dev account by entering your Site Slug and API Key

== Frequently Asked Questions ==

= Where do I find my API Key? =

Sign up or log in at [w2agent.dev](https://w2agent.dev), add your site, and copy the webhook token from your site dashboard.

= Does this slow down my site? =

No. Endpoints are only invoked when `/llms.txt` or `/.well-known/agent-card.json` is requested — typical visitors never trigger these routes. The generated text is cached for up to one hour and cleared whenever a post is saved, trashed, restored, or deleted, or the site title or tagline changes.

= Does this work with WooCommerce? =

Yes. Public custom post types that WordPress includes in search (WooCommerce products, for example) are included in the generated llms.txt. Types that are not searchable, such as many page-builder types, are left out. Use the `w2agent_post_types` filter to add or remove types, or the `w2agent_include_post` filter (receives `true` and the post, returns a boolean) to drop single items, for example gated by a membership plugin:

`add_filter( 'w2agent_post_types', function ( $types ) { $types[] = 'my_type'; return $types; } );`

= Does it work on multisite or in a subdirectory? =

Each site generates its own llms.txt. The `data/agent-card.json` file is served by the main site only. A site in a subdirectory serves `/blog/llms.txt` under its own path and needs pretty permalinks (rewrite rules through `index.php`); it cannot serve the origin-root `robots.txt` or `/.well-known/`.

= Can I use it with the plugin generated by `w2agent integrate`? =

Yes. Install the generated plugin in its own folder (`w2agent-site`). When it is active, it serves the front end (`/llms.txt`, `/llms-full.txt`, link tag, robots.txt) and this plugin keeps its settings page and platform notifications. This plugin does not serve `/llms-full.txt`.

== External services ==

This plugin can notify the w2agent platform when your content changes.

* Service: w2agent, [https://w2agent.dev](https://w2agent.dev)
* When: only after you enter a Site Slug and API Key under **Settings → w2agent**, and then each time a post is saved. Until you configure both, nothing is sent.
* What is sent: a request to a URL that contains your Site Slug, with the trigger name (`wordpress`) and the ID of the changed post in the body and your API Key as a bearer token. No post content is sent.
* Terms of service and privacy policy: [https://w2agent.dev](https://w2agent.dev)
